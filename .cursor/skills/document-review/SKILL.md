# Document Review

변경된 Markdown 문서를 검토하고 의미가 유지되는 범위에서 정리한다.

## Scope

기본적으로 `git diff --name-only`에서 확인된 Markdown 파일을 검토한다.

전체 검토 요청 시 다음 경로를 확인한다.

- `README.md`
- `CLAUDE.md`
- `AGENTS.md`
- `.claude/**/*.md`
- `.cursor/**/*.md`
- `docs/**/*.md`

다음 문서는 검토 대상에서 제외한다.

- `docs/과제_파일업로드_AI개발.md`: 사용자가 작성하지 않은 원본 과제 설명 문서

커밋 전 검토에서는 `docs/WORKFLOW.md`가 변경 목록에 없어도 항상 포함해 각 단계의 현재 상태를 확인한다.

## Rules

- 요구사항, 정책, 수치, 기술명, 경로, 명령어와 체크 상태를 임의로 변경하지 않는다
- 문서 내용을 현재 코드, 설정, 결정 사항과 구현 진행 상태에 대조한다
- 구현되지 않은 기능을 완료된 것으로 표현하지 않는다
- 미결정 사항을 확정된 내용처럼 표현하지 않는다
- 한국어 설명문은 `~한다`, `~이다` 체계로 통일한다
- 가운뎃점(`·`)을 사용하지 않는다. 나열에는 쉼표나 "와/과"를 쓰고, Mermaid 노드처럼 공간이 제한된 경우에는 슬래시(`/`)를 쓴다
- Mermaid 노드 안에서 줄바꿈은 `\n`이 아니라 `<br/>`를 쓰고, 노드 텍스트는 `["텍스트<br/>텍스트"]`처럼 따옴표로 감싼다
- 같은 개념에는 같은 용어를 사용한다
- 불필요한 반복, 구어체와 과도하게 긴 문장을 정리한다
- 제목 단계, 목록, 표, 코드 블록과 내부 링크 형식을 확인한다
- 문서별 책임에 맞지 않는 내용은 임의로 이동하지 않고 적절한 위치를 제안한다
- 의미 변경 가능성이나 문서 간 충돌이 있으면 직접 수정하지 않고 보고한다
- `docs/WORKFLOW.md`의 각 단계 `현재 상태`가 실제 커밋과 진행 상황에 맞는지 확인하고, 불일치하면 갱신한다

## Output

검토 후 다음 내용을 보고한다.

- 수정한 파일과 주요 변경 사항
- 코드, 설정, 문서와 진행 상태 사이의 불일치
- 직접 수정하지 않은 충돌 또는 미결정 사항
- 문체, 용어, Markdown과 내부 링크 검증 결과
