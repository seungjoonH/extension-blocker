# Prompt Log

의미 있는 AI 작업이 끝났을 때 실제 대화와 변경사항을 바탕으로 `docs/ai/PROMPT_LOG.md`에 새 로그를 직접 추가한다.

AI는 작업 요약, 프롬프트 기록, AI 활용 과정과 최종 반영을 작성한다. 사용자의 판단과 회고는 대신 작성하지 않으며, 필요한 질문과 판단 대상만 제공한다.

## 기록 범위

다음 내용을 기록한다.

- 프로젝트에서 공통으로 사용하는 AI 도구
- 작업별 핵심 프롬프트와 입력 맥락
- AI의 주요 제안, 수정 요청과 검증 과정
- 실제 파일, 설정, 코드와 도구에 반영된 결과
- AI 결과를 그대로 반영하거나 수정하거나 제외한 사용자의 판단

다음과 같이 AI 활용이 작업 결과에 의미 있는 영향을 준 경우 사용한다.

- 요구사항 분석
- 정책 결정
- 기술 선택과 설계
- 구현 계획 작성
- 코드 구현 또는 리팩터링
- 테스트, 디버깅과 검증
- 주요 문서 작성 또는 수정
- AI 도구와 개발 환경 구성

다음 작업은 별도 로그 없이 생략할 수 있다.

- 단순 오탈자 수정
- 공백이나 줄바꿈 정리
- 동일 요청의 반복 실행
- 결과나 의사결정에 영향을 주지 않은 형식 변경
- 작업 결과에 영향을 주지 않은 단순 확인

## 문서 구조

`docs/ai/PROMPT_LOG.md`는 다음 구조를 사용한다.

```markdown
# Prompt Log

AI 활용 과정과 사용자의 판단을 작업 단위로 기록한다.
기록은 작업 순서에 따라 시간 오름차순으로 배치한다.

## 공통 AI 도구

[프로젝트 전체에서 사용하는 AI 도구 설명]

## 작업 기록

## 001. [작업 제목]

...

---

## 002. [작업 제목]

...
```

- `공통 AI 도구`는 특정 작업 번호에 종속되지 않는다
- `공통 AI 도구`는 `작업 기록`보다 위에 위치한다
- 작업 로그는 `001`, `002`, `003` 순서로 아래에 추가한다
- 가장 오래된 로그가 위에, 가장 최근 로그가 아래에 위치한다
- 로그 번호는 작성 순서를 의미하며 계속 증가한다
- 기존 번호를 다시 정렬하거나 변경하지 않는다
- 각 로그 사이에는 `---`를 사용한다
- 첫 로그 위와 마지막 로그 아래에는 구분선을 추가하지 않는다

제목, 안내문, `공통 AI 도구`, `작업 기록`이 없으면 먼저 추가한다.

## 작업 로그 구성

각 작업 로그에는 다음 내용을 작성한다.

- 작업 요약: 작업의 목적과 전체 결과
- 프롬프트 기록: 핵심 사용자 입력과 요청 의도 또는 재요청 이유
- AI 활용 과정: AI의 주요 제안, 사용자의 방향 수정과 검증 과정
- 최종 반영: 실제로 반영된 파일, 설정, 코드와 도구
- 나의 판단과 회고: 실제로 필요한 경우에만 생성

해당 작업에서만 사용한 도구가 중요하면 `이번 작업에서 사용한 AI 도구`를 선택적으로 추가할 수 있다.

## 프롬프트 기록

실제 대화에서 사용자가 입력한 프롬프트 중 작업의 흐름을 이해하는 데 꼭 필요한 것만 기록한다.

### 형식

````markdown
### 프롬프트 기록

<details>
<summary>프롬프트 보기</summary>

#### 1. 최초 요청

```
[실제 프롬프트 원문 또는 핵심 발췌]
```

**요청 의도**

[사용자가 명시한 요청 의도]

#### 2. 방향 수정

```
[실제 프롬프트 원문 또는 핵심 발췌]
```

**재요청 이유**

[사용자가 명시한 재요청 이유]

</details>
`````

* `<summary>` 문구는 `프롬프트 보기`로 통일한다
* 프롬프트는 인용구가 아니라 코드 블록으로 표시한다
* `<details>` 내부와 외부에 불필요한 구분선을 추가하지 않는다

### 선별 기준

다음 입력만 핵심 프롬프트로 기록한다.

* 작업을 시작하게 만든 최초 요청
* 요구사항, 범위, 정책 또는 설계를 결정한 요청
* AI 결과의 중요한 문제를 지적하고 방향을 바꾼 요청
* AI 결과를 수정하거나 거부한 근거가 드러나는 요청
* 검증 결과에 따라 구현이나 작업 방식을 변경한 요청
* 최종 결과에 의미 있는 영향을 준 제약 조건

다음 입력은 기록하지 않는다.

* 단순 확인 질문
* 명령 실행 승인
* 동일한 목적의 반복 요청
* 오탈자, 어미와 문장 길이만 수정하는 요청
* 결과나 판단에 영향을 주지 않은 형식 변경
* 이전 프롬프트의 의미를 바꾸지 않는 재표현
* 작업 결과와 무관한 대화
* 같은 판단을 여러 표현으로 반복한 요청

일반적인 작업은 3개에서 5개, 복잡한 작업도 최대 7개를 넘기지 않는다. 같은 방향의 연속 요청은 하나로 묶고, 중요도가 낮으면 생략한다.

다음 질문을 선별 기준으로 사용한다.

> 이 프롬프트를 제거하면 작업의 시작 배경, 중요한 방향 변경 또는 사용자의 판단을 이해하기 어려워지는가?

그렇지 않다면 기록하지 않는다.

### 원문과 발췌

* 짧은 핵심 프롬프트는 원문 그대로 기록한다
* 긴 프롬프트는 핵심 요구사항만 발췌한다
* AI가 발췌 내용을 자연스럽게 다시 작성하지 않는다
* 서로 떨어진 문장을 하나의 원문처럼 임의로 합치지 않는다
* 일부를 생략하면 `[...]`로 표시한다
* 실제 대화에서 확인되지 않는 프롬프트를 생성하지 않는다
* 비밀 키, 토큰, 비밀번호와 개인정보는 기록하지 않는다

### 요청 의도와 재요청 이유

* 최초 요청에는 `요청 의도`를 사용한다
* 결과 수정이나 방향 변경에는 `재요청 이유`를 사용한다
* 사용자가 직접 밝힌 내용만 작성한다
* 사용자의 동기나 판단을 추정하지 않는다
* 1문장에서 2문장으로 제한한다
* 명확하지 않으면 다음과 같이 비워 둔다

```markdown
**요청 의도**

> 작성 필요
```

`요청 의도`와 `재요청 이유`는 프롬프트 입력 맥락을 기록하는 영역이므로 회고와 중복된다는 이유로 생략하지 않는다.

## 공통 AI 도구

프로젝트 전체에서 공통으로 사용하는 Agent, Skill, Plugin, MCP, 라이브러리와 도구는 `PROMPT_LOG.md` 상단에 한 번만 기록한다.

각 항목에는 다음 내용을 포함한다.

* 도구명
* 프로젝트에서 맡는 역할
* 어디에 사용하는지
* 선택하거나 구성한 이유

```markdown
## 공통 AI 도구

- **[도구명]**: [역할, 사용 위치와 선택 이유]
```

규칙은 다음과 같다.

* 특정 작업 번호에 종속시키지 않는다
* 내용을 지나치게 축약하지 않는다
* 실제 문서와 작업에서 확인되는 사실만 작성한다
* 확인되지 않은 사용 사례를 추가하지 않는다
* 새로운 공통 도구가 도입된 경우에만 갱신한다
* 특정 작업에서만 일회성으로 사용한 도구는 추가하지 않는다

## 작업별 AI 도구

특정 작업에서 실제로 호출하거나 중요한 역할을 한 도구만 선택적으로 기록한다.

```markdown
### 이번 작업에서 사용한 AI 도구

- **도구명 또는 스킬명**: 해당 작업에서 구체적으로 사용한 위치와 결과
```

* 공통 도구 목록 전체를 반복하지 않는다
* 사용하지 않은 도구를 기록하지 않는다
* 공통 영역의 일반적인 역할이나 선택 이유를 반복하지 않는다
* 해당 작업의 구체적인 사용 위치와 결과만 기록한다
* 별도로 강조할 내용이 없으면 섹션을 생략한다
* `AI 활용 과정`과 중복되면 섹션을 추가하지 않는다
* Superpowers는 가능하면 구체적인 스킬명을 기록한다
* Context7은 확인한 라이브러리나 기술 문서를 기록한다
* `document-review`, `prompt-log`, `commit-commands`도 실제 사용한 경우에만 기록한다

## 판단과 회고

`나의 판단과 회고`는 도구를 선택한 이유가 아니라, AI 결과를 사용자가 어떻게 처리했는지 기록하는 영역이다.

도구의 역할과 선택 이유는 `공통 AI 도구` 또는 `이번 작업에서 사용한 AI 도구`에서 다룬다.

다음 세 가지 중 실제로 해당하는 질문만 생성한다.

```markdown
### 나의 판단과 회고

#### AI의 제안 중 그대로 반영한 내용은 무엇인가?

[이번 작업에서 확인된 판단 대상을 짧은 목록으로 제시]

> 작성 필요

#### AI의 제안을 수정해서 반영한 내용은 무엇인가?

[이번 작업에서 확인된 판단 대상과 사용자가 발견한 문제를 짧은 목록으로 제시]

> 작성 필요

#### AI의 제안 중 제외한 내용은 무엇인가?

[이번 작업에서 확인된 판단 대상과 제외 여부를 검토한 내용을 짧은 목록으로 제시]

> 작성 필요
```

* 해당하지 않는 질문은 생략한다
* 세 가지 모두 해당하지 않으면 섹션 전체를 생략한다
* AI는 회고 답변을 작성하지 않는다
* 판단 대상 목록에는 확정된 작업 사실만 작성한다
* 사용자의 판단이나 결론을 대신 작성하지 않는다
* 목록은 회고 범위를 안내하는 용도로만 사용한다

AI가 놓치거나 잘못 제안한 부분을 사용자가 직접 확인한 경우 별도 질문으로 만들지 않는다.

* 수정해서 반영했다면 `수정해서 반영한 내용`에 포함한다
* 사용하지 않았다면 `제외한 내용`에 포함한다

### 질문 작성 규칙

* 사용자가 실제로 선택했거나 문서에 확정된 대상만 언급한다
* 정답이나 판단 근거를 질문에 미리 포함하지 않는다
* 사용자가 말하지 않은 동기, 문제 인식과 대안 비교를 추정하지 않는다
* 질문 하나에는 하나의 판단 유형만 묻는다
* 정답을 암시하는 상황 설명을 붙이지 않는다
* 질문은 짧고 중립적으로 작성한다
* 도구 선택 이유와 AI 결과 판단을 혼합하지 않는다

### 회고 질문 예시

나쁜 예:

> AI가 바로 구현에 들어가는 문제를 줄이기 위해 `AI_WORKFLOW.md`를 먼저 작성한 이유는 무엇인가?

문제점:

- 사용자가 문제라고 말하지 않은 상황을 확정함
- 선택 목적과 기대 효과를 질문 안에 미리 포함함

좋은 예:

> 기능 구현 전에 `AI_WORKFLOW.md`를 작성한 이유는 무엇인가?

## 저장 규칙

* 새 로그는 기존 마지막 로그 아래에 추가한다
* 로그는 시간 오름차순으로 유지한다
* `001`이 가장 위에 위치한다
* 사용자가 작성한 기존 회고는 명시적인 요청 없이 수정, 삭제하거나 덮어쓰지 않는다
* 기존 로그의 순서와 내용을 임의로 변경하지 않는다
* `공통 AI 도구`는 항상 `작업 기록` 위에 유지한다

해당하지 않는 회고 질문은 생략한다.

`이번 작업에서 사용한 AI 도구`가 필요하면 `AI 활용 과정` 뒤에 추가한다. `AI 활용 과정`과 중복되면 생략한다.

## 작성 규칙

* 실제 대화와 변경사항에서 확인된 내용만 작성한다
* 수행하지 않은 작업이나 사용하지 않은 도구를 기록하지 않는다
* 사실로 확인되지 않은 내용을 작성하지 않는다
* 작업 요약은 목적과 결과 중심으로 간결하게 작성한다
* 설치와 설정의 시행착오는 세부 절차보다 핵심 결과만 남긴다
* 같은 내용을 여러 섹션에 반복하지 않는다
* 프롬프트 전문은 `프롬프트 기록`에만 작성한다
* `AI 활용 과정`에는 AI의 제안, 검증 결과와 실제 방향 변경을 기록한다
* `최종 반영`에는 실제로 남은 결과만 기록한다
* 회고에는 AI 결과를 그대로 반영하거나 수정하거나 제외한 판단만 다룬다
* 사용자의 선택과 판단 근거를 추정하지 않는다
* 문서 본문에서는 가운데점 문자를 사용하지 않는다
* 병렬 표현에는 쉼표, 접속 표현 또는 문장 분리를 사용한다

## 출력

로그를 `docs/ai/PROMPT_LOG.md`에 직접 반영한다.

대화창에는 다음 내용만 간단히 보고한다.

* 변경한 파일 경로
* 추가한 로그 번호와 제목
* 기록한 핵심 프롬프트 개수
* `공통 AI 도구` 갱신 여부와 신규 항목 수
* `이번 작업에서 사용한 AI 도구` 항목 수
* 사용자가 작성해야 하는 회고 질문 수
* 사용자가 작성해야 하는 요청 의도 또는 재요청 이유 수
* 사실 확인이 필요한 내용

로그 전체를 대화창에 다시 출력하지 않는다.

사용자의 요청 없이 스테이징하거나 커밋하지 않는다.
