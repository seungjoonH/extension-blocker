# Prompt Log

AI 활용 과정과 사용자의 판단을 작업 단위로 기록한다.
기록은 작업 순서에 따라 시간 오름차순으로 배치한다.

## 공통 AI 도구

- **Claude Code**: 프로젝트의 AI 워크플로 구성, 문서 작성, 코드 수정, 검증과 기록을 수행하는 주 Agent로 사용. Skills, MCP, 프로젝트 규칙과 플러그인을 하나의 실행 환경에서 연결하고, 정의한 작업 흐름을 반복 적용하기 위해 선택함
- **Superpowers**: 기획, 계획 작성, TDD, 체계적 디버깅과 완료 전 검증 절차를 실제 작업 단계에 적용하기 위해 사용. AI가 바로 구현에 들어가지 않고 일정한 개발 절차를 따르도록 구성함
- **Context7**: 라이브러리의 최신 API와 설정을 공식 문서 기준으로 확인하기 위해 사용. AI의 기존 지식이나 버전 차이로 발생할 수 있는 오류와 추측을 줄이기 위해 MCP로 연결함
- **document-review**: Markdown 문서의 문체, 형식, 용어와 프로젝트 상태의 정합성을 일관되게 검토하기 위해 만든 프로젝트 전용 스킬
- **prompt-log**: 핵심 프롬프트, AI 활용 과정과 사용자 판단을 작업 단위로 기록하고 누락을 방지하기 위해 만든 프로젝트 전용 스킬. AI는 사용자의 회고를 대신 작성하지 않고 질문과 판단 대상을 제공하도록 제한함
- **commit-commands**: 검증이 끝난 변경사항을 논리적인 작업 단위로 검토하고 커밋하기 위해 사용. 커밋 전 변경 범위와 메시지를 확인하는 절차에 적용함

## 작업 기록

## 001. AI 개발 워크플로 구성

### 작업 요약

기능 구현 전에 AI 도구와 스킬의 역할과 실행 순서를 `AI_WORKFLOW.md` 로 먼저 정의하고, 이를 뒷받침하는 프로젝트 스킬을 구성한 뒤 실제 설치와 인식 상태를 검증했다.

#### 1. 최초 요청

docs/ai/AI_WORKFLOW.md를 기준으로 현재 AI 개발 환경이 올바르게 구성되었는지 확인해줘. [...] 문제를 직접 수정하거나 스테이징하거나 커밋하지 마.

**요청 의도**

> 기능 구현을 시작하기 전에 AI_WORKFLOW.md에 정의한 AI 개발 환경이 실제로 올바르게 구성되어 있는지 확인하고, 수정이 필요한 부분을 먼저 파악하기 위해 요청했습니다.

#### 2. Superpowers, Context7 중복 정리 지시

```
공식 마켓플레이스의 Superpowers 하나만 유지 [...] 별도로 추가한 마켓플레이스 또는 중복 설치본 제거
```

**요청 의도**

> AI가 점검한 결과 Superpowers와 Context7이 중복 등록되어 있음을 확인했습니다. 동일한 도구가 여러 경로로 등록되면 실제로 어떤 구성을 사용하는지 불명확해질 수 있다고 생각했습니다. 따라서 공식 설치본만 유지하고 중복 구성을 제거해 AI 개발 환경을 명확하게 정리하기 위해 요청했습니다.

#### 3. prompt-log 회고 대필 금지 지시

```
prompt-log를 사용해서 이번 AI 개발 워크플로 구성 작업의 로그 초안을 생성해줘. [...] 작업 내역과 AI 활용 항목만 채우고, 나의 판단과 회고 항목은 비워 둬.
```

**요청 의도**

> AI 활용 과정과 작업 결과는 자동으로 정리하되, 사용자의 판단과 회고는 실제 작업을 진행한 제가 직접 작성해야 한다고 생각했습니다. 따라서 AI가 회고 내용을 대신 작성하지 않고 작성 영역만 남기도록 요청했습니다.

#### 4. 프롬프트 기록 추가 요청

```
prompt-log 스킬의 프롬프트 기록 방식과 현재 docs/ai/PROMPT_LOG.md의 001번 로그를 수정해줘. 이번 수정의 목적은 AI에 입력한 핵심 프롬프트를 기록하되, 로그가 지나치게 길어지지 않도록 가독성과 선별 기준을 강화하는 것이야.
```

**요청 의도**

> 과제에서 AI에 입력한 프롬프트와 재질문 과정을 기록하도록 요구하고 있어, 작업의 흐름에 영향을 준 핵심 프롬프트를 남길 필요가 있다고 생각했습니다. 다만 모든 대화를 기록하면 로그가 지나치게 길어질 수 있어, 핵심 프롬프트만 선별하고 접이식으로 구성해 가독성을 유지하기 위해 요청했습니다.

### AI 활용 과정

- Superpowers, Context7, commit-commands의 실제 설치와 인식 상태를 점검해 중복 등록과 설치 오류를 정리함
- `prompt-log`가 사용자의 판단과 회고를 대신 작성하지 않도록 역할을 제한하는 정책을 AI가 제안해 반영함
- `AI_WORKFLOW.md`, `CLAUDE.md`, 각 `SKILL.md` 간 설명 불일치를 AI가 점검해 제시하고 수정함

### 최종 반영

- `docs/ai/AI_WORKFLOW.md` 작성 및 `document-review`, `prompt-log` 프로젝트 스킬 구성
- `prompt-log`가 사용자 판단을 대신 작성하지 않도록 정책 확정
- Superpowers, Context7, commit-commands 중복 등록과 설치 오류 정리
- 문서 간 설명 불일치 수정 및 `.gitignore`에 `.claude/settings.local.json` 추가

### 나의 판단과 회고

#### AI의 제안 중 그대로 반영한 내용은 무엇인가?

이번 작업에서는 다음 제안이 실제 반영 후보에 포함되었습니다.

- 기능 구현 전에 `AI_WORKFLOW.md`를 먼저 작성하는 방식
- `document-review`와 `prompt-log`를 프로젝트 전용 스킬로 분리하는 방식

> 기능 구현 전에 AI 활용 방식과 작업 절차를 먼저 정의하는 제안을 반영했습니다. 구현 후 활용 과정을 복기하면 실제 판단이나 수정 과정이 누락될 수 있다고 생각했습니다. 또한 문서 검토와 AI 활용 기록의 역할이 다르므로 `document-review`와 `prompt-log`를 각각 분리해 구성했습니다.

#### AI의 제안을 수정해서 반영한 내용은 무엇인가?

이번 작업에서는 다음 항목을 여러 차례 수정했습니다.

- `prompt-log`의 로그 구조와 분량
- 고정된 회고 항목을 작업 맥락에 맞는 질문으로 변경
- 유도성 있는 회고 질문을 중립적인 질문으로 변경
- 모든 프롬프트가 아닌 핵심 프롬프트만 기록하도록 범위 제한

> 초기 `prompt-log`에는 실제 입력 프롬프트가 포함되지 않았고, 회고 질문에 사용자의 판단 근거가 미리 들어가 있었습니다. 이를 직접 확인한 뒤 핵심 프롬프트와 요청 의도를 기록하도록 보완하고, 작업 맥락에 맞는 중립적인 회고 질문을 제공하도록 수정했습니다. 또한 로그가 길어지지 않도록 핵심 프롬프트만 접이식으로 기록하도록 변경했습니다.

#### AI의 제안 중 제외한 내용은 무엇인가?

이번 작업에서는 다음 제안이나 작성 방식의 제외 여부를 판단했습니다.

- AI가 사용자의 판단과 회고 답변까지 대신 작성하는 방식
- 작업 결과에 영향을 주지 않은 모든 대화를 프롬프트 로그에 기록하는 방식
- 도구 선택 이유와 AI 결과 판단을 하나의 회고 영역에 함께 작성하는 방식

> AI가 사용자의 판단과 회고까지 작성하는 방식은 제외했습니다. 회고에는 실제 사용자의 선택과 근거가 들어가야 한다고 생각했기 때문입니다. 또한 모든 대화를 기록하면 핵심 판단 과정이 묻힐 수 있어 제외했으며, 도구 선택 이유는 공통 AI 도구 영역으로 분리하고 회고는 AI 결과를 채택, 수정, 제외한 판단에만 집중하도록 정리했습니다.
