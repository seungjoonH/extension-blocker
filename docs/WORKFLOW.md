# Workflow

프로젝트가 어떤 순서로 진행되고 각 단계에서 무엇이 만들어지는지를 한눈에 보여주는 안내 문서다. 세부 요구사항과 기술 설계는 반복하지 않고 각 단계의 산출물 문서로 연결한다.

## 진행 원칙

- 요구사항을 먼저 확정한 뒤 기획과 기술 설계를 진행한다
- 각 단계는 이전 단계에서 확정된 문서를 기준으로 수행한다
- 결정되지 않은 내용을 AI가 임의로 확정하지 않는다
- 각 단계가 끝날 때 문서 품질과 구현 결과를 검토한 뒤 다음 단계로 이동한다

## 단계

### 1. AI workflow 설정

- 목적: AI 도구와 스킬의 역할, 적용 기준과 실행 순서 정의
- 주요 작업: Superpowers, Context7 MCP, 프로젝트 전용 스킬(`document-review`, `prompt-log`) 구성과 설치/인식 상태 점검
- 산출물: [`CLAUDE.md`](../CLAUDE.md), [`docs/ai/AI_WORKFLOW.md`](ai/AI_WORKFLOW.md)
- 현재 상태: 완료

### 2. 요구사항 분석과 구체화

- 목적: 구현할 요구사항과 결정이 필요한 쟁점 구분
- 주요 작업: 필수 요구사항 정리, 고려사항별 구현 여부와 판단 근거 논의, 검증 체크리스트 작성
- 산출물: [`docs/specs/REQUIREMENTS.md`](specs/REQUIREMENTS.md)
- 현재 상태: 완료

### 3. 기획

- 목적: 확정된 요구사항을 화면과 사용자 흐름으로 구체화
- 주요 작업: Superpowers를 활용해 사용자 흐름, 화면 구성, 주요 상태를 구체화
- 산출물: [`docs/specs/PLANNING.md`](specs/PLANNING.md)
- 현재 상태: 완료

### 4. 기술 설계

- 목적: 요구사항과 기획을 구현 가능한 기술 구조로 확정
- 주요 작업: 데이터 모델, API, Supabase Postgres, Supabase Storage, 파일 검증과 저장 흐름 구체화
- 산출물: [`docs/specs/DESIGN.md`](specs/DESIGN.md)
- 현재 상태: 완료

### 5. 구현

- 목적: 확정된 요구사항과 설계를 동작하는 기능으로 구현
- 주요 작업: 작은 작업 단위로 구현하고, 필요한 검증과 AI 활용 기록을 함께 남김
- 산출물: 소스 코드, [`docs/ai/PROMPT_LOG.md`](ai/PROMPT_LOG.md) 갱신
- 현재 상태: 완료

### 6. 검증

- 목적: 구현이 요구사항과 설계를 충족하는지 확인
- 주요 작업: 필수 요구사항, 서버 검증, 예외 처리, 접근성, 반응형, 문서와 구현의 일치 여부 확인
- 산출물: 검증 결과
- 현재 상태: 진행 예정

### 7. 배포와 제출 점검

- 목적: 배포와 제출 요건 확인
- 주요 작업: 배포 URL, 환경 변수, README, 스키마, `CONSIDERATIONS.md`, `PROMPT_LOG.md` 등 제출 필수 항목 확인
- 산출물: 배포된 사이트, 제출 문서 일체
- 현재 상태: 진행 예정
